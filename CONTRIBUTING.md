# Contributing

## Branch naming
Use `feature/<short-description>` (e.g. `feature/roster`, `feature/rename`). Branch from an up-to-date `main`.

## Commit messages
Short, present-tense summary of what changed (e.g. "add StudentNotFound and find command").

## Pull before pushing
Always run `git pull` on `main` before merging a feature branch in.

## Who may merge to main
Anyone may merge their own branch once it's tested locally and runs without errors. Nobody commits directly to `main` except for urgent fixes to a broken build, and those should be flagged to the team.

## Breaking changes
**Announce renames, signature changes, or removed functions to the team before pushing them.** This is the one rule that would have prevented Stage 3.
